# DR1 Oracle：前置观测器的收益上限（2026-10-05，用户定）

## 问题

DR1（真 Kp/Kd、质心 ±5 cm、质量 −1…+3 kg、气弹簧 ×0.9–1.5、延迟 0–10 ms）换来参数偏差鲁棒性，代价是名义平地 vx 误差约 2 倍、
中速前后晃（`docs/plan/rough_wide_dr_20261003.md`）。用户计划加前置观测器（历史 → 低维隐向量，CTS + ROA）。
先量上限：actor 直接知道真实 DR 参数时，这部分代价能拿回多少。此前 WideDR 上的 Oracle（1fa00ca）受恢复系数实现问题污染，不适用于 DR1。

## 改动

`SE3-WheelLegged-Rough-Exp-DR1-Oracle`（56b9de4）：相对当前默认唯一差异是 actor 观测末尾追加 31 维真实 DR 参数
（28 维 DR 回读、左右气弹簧力、动作延迟），critic 不变；不可部署（runtime 不认这些项）。
配置核对：与默认相比只多 actor 的 3 个观测项，事件、奖励（含参数）、指令、终止、课程逐项一致（`.scratch/widedr_eval/dump_cfg_full.py`）。

assets 无变化）。注意规模不同：基线四卡 × 1170（共 4680 env），Oracle 按用户要求六卡 × 1170（共 7020 env）。

## OracleVel（2026-10-05，用户定）

actor 默认与 Oracle 都没有机身线速度（只有 critic 有），速度只能从轮速间接推，而 DR1 的质心配平、打滑、延迟会扰乱这个换算。
`SE3-WheelLegged-Rough-Exp-DR1-OracleVel`（0dd79e0）= Oracle + actor 机身系线速度 3 维，与 Oracle 只差这一项（配置逐项核对）。
whtws 六卡 × 1170、5000 轮、seed 42，W&B `x0xavu14`，PGID 1887243，state `20261005T174105Z`。与 Oracle 同规模，可直接对比。

### Oracle / OracleVel 结果（4800–4999 轮；OracleVel / Oracle / 基线 jrvpex39）

平地 tracking 0.852 / 0.700 / 0.730，vx 误差 0.473 / 0.660 / 0.651，台阶航向 10.3° / 13.6° / 11.9°，stairs_up 6.20 / 6.01 / 5.99，
yaw 误差 1.64 / 0.94 / 0.96，跳跃列等级 0.47 / 0.40 / 4.86，catastrophic 0.041 / 0.050 / 0.067，回报 68.6 / 57.7 / 72.1。
- 只给 DR 参数不改善平地跟踪；再加机身速度后平地跟踪明显变好 → DR1 平地跟踪变粗主要来自速度估计。
- OracleVel 转向变差（全程如此），原因未明。
- 两条 Oracle（不同机器）都没学会跳跃，而同为六卡、不加特权输入的 NoRest / OldDR 都学会 → 嫌疑是那 31 维 DR 参数输入。
- OracleVel actor 对速度各分量的敏感度（扰动 1σ）：vx 2.11（全网络最大）、vz 0.51、vy 0.28；原观测各组 0.63–1.20。

## Vel / Vx（2026-10-06，用户定）

在当前默认上只给 actor 速度、不加 DR 参数：`Exp-Vel`（3 维，nulltask1，W&B `fpuf21dr`）、`Exp-Vx`（只给 vx，whtws，W&B `qnd9o87r`），
均 18c5062、六卡 × 1170、5000 轮、seed 42。配置核对：各自与默认只差一个 actor 观测项。
- Vel 对 OracleVel：DR 参数 31 维的作用，以及跳跃学不出是否由它引起。
- Vx 对 Vel：vy / vz 的贡献；若 Vx ≈ Vel，观测器只需估 vx。

结果（2240–2340 轮；Vel / Vx / OracleVel / Oracle / 基线 jrvpex39）：平地 tracking 0.815 / 0.797 / 0.842 / 0.663 / 0.721，vx 误差 0.577 / 0.583 / 0.546 / 0.731 / 0.659，台阶航向 10.7° / 10.3° / 13.1° / 18.0° / 12.9°，跳跃列等级 0.32 / 0.45 / 0.53 / 0.42 / 3.79。
2026-10-06 用户判断已收敛，Vel 于 2593 轮、Vx 于 2504 轮停止。
- 速度收益基本来自 vx：只给 vx 拿到 3 维速度的大部分收益；在速度之外再给 DR 参数只多一点。观测器只需估准 vx。
- 跳跃：Vel / Vx 没有 DR 参数也学不会，排除「31 维 DR 参数」的嫌疑；但四条学不会的 run 全是六卡 × 1170（7020 env），学会的基线是四卡 × 1170、NoRest / OldDR 是六卡 × 1365，规模混杂未排除——需六卡 × 1170 的默认基线才能分清是特权输入还是规模。

## 判据

训练端同轮次对比基线（回报、yaw 误差、平地 tracking、stairs_up / 跳跃列等级、catastrophic）。Oracle 不能 sim2x 回放；
如需评测端，可在训练环境里用 checkpoint 做确定性回放（放 Pod 上跑）。
- 明显好于基线 → 信息是 DR1 代价的来源，做前置观测器。
- 与基线持平 → 观测器在 DR1 下没有上限空间，转向收窄 DR 范围（如质心 ±2 cm）。

## 跳跃学不会的定位（2026-10-06）

学会的 run（Base `jrvpex39` σ0.07 4680 env、Base010 `h7tyzjql` σ0.10 4680、NoRest / OldDR σ0.10 8190）对学不会的 run
（Oracle / OracleVel / Vel / Vx / VxObserver / SpringFF 6×1170、WheelTN 7×1500，均 σ0.07）：跳跃指令分配率都是 0.10，
但学不会的一组"偏离参考终止"占终止的 0.51–0.75、处于跳跃中的 env 只有 0.014（学会的 0.024–0.027），600–1000 轮内没把偏离终止压下来，
拿不到完整跳跃的学习信号。f090dbe → 56b9de4 默认路径只差 σ 0.10 → 0.07，参考轨迹 / assets / 依赖锁未变；同 4680 规模下 σ0.07 反而学得更快。
剩下"actor 输入改动"与"规模（≥ 7020 env）/ σ×规模"分不开：当前默认从未在 ≥ 7020 env 跑过。
补纯默认基线：nulltask1 六卡 × 1170、5000 轮、seed 42，4832d15（默认路径与 56b9de4 相同），W&B `zqfk10rn`，state `20261006T122507Z-19922`。
判据：学会跳 → 原因在给 actor 加 vx / DR 信息；也学不会 → 原因在规模或 σ×规模。
