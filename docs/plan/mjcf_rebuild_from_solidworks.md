# 从 SolidWorks 规范重导出 MJCF（v4）

> 目的：把 `serialleg_closed_chain_v3_train_obb_trim.xml` 里靠手填和事后置换轴堆出来的坐标，
> 换成一条「CAD → URDF → MJCF」可复现的链路。本文是 CAD 侧的作业指导书，
> 后半段是转换侧的契约。

## 0. 三条底线（先看，再动 CAD）

**0.1 产出的是 v4，不覆盖 v3。**
一旦几何或惯性变了，所有已训练 checkpoint 的默认站姿、recovery cache、ONNX 部署包络全部失效
（参见 `bd5866e` 那次静平衡重标定的后果）。新模型走
`assets/robots/serialleg/mjcf/serialleg_closed_chain_v4.xml`，v3 原样留着，
等 v4 跑通对照训练再切默认。

**0.2 link / joint 名字一个都不改。**
`lf0_Link` / `lf1_Link` / `l_drive_bar_Link` / `l_coupler_Link` / `l_wheel_Link` 及对应
`*_Joint` 被 28 个文件引用，包括部署契约
`submodules/se3-sim2x/src/se3_runtime/policy_contract.py`。文件名和 mesh 名可以整理，
link/joint 名不能动。在导出器里就按这套名字填。

**0.3 右侧关节符号约定暂时保持 `axis="0 -1 0"`。**
当前约定下镜像姿态是 `q_R = -q_L`。如果全部改成 `0 1 0`，镜像姿态变成 `q_R = q_L`——
客观上更好读、对称性奖励也更干净，但会翻转右侧所有关节的正方向，
部署固件和 `policy_contract.py` 要同步改。**这个决定不影响你在 CAD 里怎么做**
（CAD 侧统一按「Y 轴指向车体左侧」建坐标系），由我在转换脚本里二选一。先按低风险的保持不变。

---

**0.4 先只做「纯底盘」变体，但要给带云台留口子。**
现在导出的是 chassis_only：云台、弹仓、裁判系统全部 **压缩 Suppress（不是删除 Delete）**。
「压缩」是可逆的，以后要带云台版本就是右键「解除压缩」，不用重装配合关系。
MJCF 侧对应的设计是「一个文件 + 一个可删除的 `gimbal_Link` 子 body」，
这样 `base_link` 的 `<inertial>` 永远只写纯底盘，加不加云台都不用重算。详见 §1.7 和 §5.2。

### 1.1 建立总装坐标系 `base_link_cs`

这是整条链路的根，也是上次出问题的地方。

`插入 → 参考几何体 → 坐标系`，在总装（顶层装配体）里建一个，命名 `base_link_cs`：

- **X = 车头前进方向**
- **Y = 车体左侧**（左腿那一侧）
- **Z = 向上**

三个轴用「选一条边 + 反转方向(Reverse Direction)勾选框」逐个指定，不要靠默认。
建完用 `工具 → 评估 → 质量属性`，把「输出坐标系」设成 `base_link_cs`，
确认三个轴方向和你预期一致（质心 z 应该是正的、在机身内部）。

原点位置建议放在**两个髋轴连线的中点**——这样 `base_link` 原点到髋轴就是纯 y 平移
`(0, ±0.16885, 0)`，和现在的模型一致，转换脚本不用做额外补偿。

> 上次的教训：总装是 Y-up，导出后靠 `[SW_Z, SW_X, SW_Y]` 事后置换。
> 这次在 CAD 里就摆正，URDF 出来直接是 ROS/MuJoCo 约定，中间不再有置换步骤。

### 1.2 保证左右真的是镜像

现在的模型里左右腿有三处对不上，都是 CAD 层面的：

| 问题 | 证据 |
|---|---|
| 小腿左右不是同一个件 | `Left_calf_link.STL` 1.84 MB vs `Right_calf_link.STL` 1.67 MB；顶点 2904 vs 2917，镜像 bbox 差 **8.0 mm** |
| 大腿也不完全一致 | 镜像差 0.21 mm（可接受但说明不是镜像件） |
| 整条右腿内收 1.5 mm | 见 §1.3 的对照表 |

做法：

1. **只装左腿**，右腿全部用 `插入 → 镜像零部件` 生成，镜像面选总装的 **右视基准面**
   （在新约定下就是 y = 0 平面）。
2. 对每个零件在镜像对话框里选：
   - 零件本身关于自己中面对称 → **要镜像的实例(Instance to Mirror)**（只是镜像实例）
   - 零件是真的有手性（左右件不同）→ **生成相反方位版本(Create opposite hand version)**，
     它会派生出一个 `xxx_MIRROR.sldprt`，几何上是**保证精确镜像**的
3. **不要**保留两个各自建模的小腿零件。当前的 8 mm 差就是这么来的。
4. 参考坐标系和参考轴一起镜像出去，不要在右侧手工重建。

镜像之后，用 `质量属性` 分别量左右腿子装配的质量和质心，
两者质量应该完全相同，质心 y 应该等值反号。**对不上就是镜像没做干净，先修这个再往下走。**

### 1.3 质量属性 —— 最要紧的一步

当前模型最大的不对称不在几何上，在这一行：

```xml
<inertial pos="-0.01780372 0.01307697 -0.03342401" mass="10.74541262"
          fullinertia="0.14395729 0.21248062 0.30929562 -0.00229101 0.00807199 -0.00039793" />
```

`base` 外壳左右完全对称（bbox 中位 0.000 mm），但**质心偏左 13.08 mm**，
整机质心因此偏 11.11 mm，静态载荷分配 **左轮 52.5% / 右轮 47.5%**。
而 `env_cfg.py:770` 的质心随机化只有 ±5 mm，band 是 [+8, +18] mm，
**策略从没见过一台左右对称的车**。

导出前必须做：

1. 每个零件都要有材料。`编辑材料` 逐个设，或者对没有实体的件用
   `工具 → 评估 → 质量属性 → 覆盖质量属性` 直接填实测质量。
2. **集中质量件单独处理**：电池、电控、图传、上层机构这类在 CAD 里是简化壳体的，
   用「覆盖质量属性」填实测质量 + 实测质心。这是 13 mm 偏心最可能的来源。
3. 选中 `base` 子装配 → `质量属性` → 输出坐标系设成 `base_link_cs`
   → **把「质量」和「质心」三个分量抄下来给我**。

   - 如果 |CoM.y| < 2 mm：说明 v3 那个 13 mm 是建模误差，v4 直接就修好了
   - 如果 |CoM.y| ≈ 13 mm：说明是真的（电池偏装之类），那要么在硬件上配平，
     要么我们把它显式写进模型并调整对称性奖励的基准

4. **称一下实车**，和 CAD 总质量（现在是 12.729 kg）比。差超过 5% 说明所有惯量都不可信。

### 1.3b CAD 质量审计结论（2026-09-06，通过 SolidWorks COM 读全部 1379 个零部件实例）

用 `scripts/` 外的一次性脚本连 SolidWorks COM，逐个读了 380 个 (零件,配置) 组合的
质量/密度/体积/材料，0 个失败。结论如下，**§1.3 那个 13 mm 之谜已破**。

#### 结论 1：13 mm 质心偏心是 CAD bug，不是实车特性

```
【电机】8009-RAU_5005          930.000 g   体积 349.526 cm3   密度    1.0   材料 'Steel'
Mirror【电机】8009-RAU_5005    349.526 g   体积 349.526 cm3   密度 1000.0   材料 ''
```

体积完全相同，**密度 1.0 是「覆盖质量属性」的标志**——原件被手工覆盖成 930 g（已向用户确认
930 g 是实测值）。而镜像件（`生成相反方位版本` 派生的）**不继承质量覆盖**，
退回默认密度 1000 kg/m³，于是 349.526 cm³ × 1 g/cm³ = 349.526 g，一分不差。

这两个 8009 在 `【装配体】电机座` 里（髋部电机座，固定在车架上 → 属于 `base_link`）。
左右差 580.5 g × 2 = **1161 g**，力臂约 0.14–0.17 m，base 约 12–13 kg
→ 推算质心横向偏移 **13–16 mm 偏左(+y)**，与 MJCF 里写的 **+13.08 mm 偏左** 数量级和方向都对上。

修正后 `电机座` 左右差从 **1156.4 g 塌到 4.6 g**。

#### 结论 2：MJCF 的 base_link 漏掉了全部装甲板（2782 g，占纯底盘 18%）

```
CAD base（修正后）    13433.2 g
装甲板合计             2782.3 g
base 去掉装甲板       10650.9 g
MJCF base_link        10745.4 g
剩余差                  -94.5 g   ← 0.9%
```

明细：`【裁判系统】装甲模块 AM02` 359.0 g ×4 = 1436 g、
`【裁判系统】装甲支架 A型 2019` 80.0 g ×8 = 640 g、碳板保护板/保险杠/插板/转接件/螺栓 706 g。

比赛规则要求步兵必装 4 块装甲板，实车上它是在的。**v4 必须把装甲板算进 base_link。**
这比 13 mm 偏心严重一个量级：18% 质量 + 装在外侧偏高位置，直接改变质心高度、
转动惯量、电机扭矩需求和倒地恢复的翻滚惯量。

### 1.6 简化：先量，后简化，顺序不能反

`26分区赛步兵总装.SLDASM` 是 152 MB，全库 317 零件 / 46 装配体 / 8 个 STEP，打开就卡。
重量分布：

```
26分区赛步兵总装.SLDASM                    152 MB
├── 【装配体】云台yaw轴总装03               60 MB   ← 变体 B 才需要
│   ├── 【装配体】p轴总装3                  58 MB
│   ├── 阿木 orin NX SUPER                 34 MB  + ORIN NX-SUPER.stp 55 MB
│   ├── 新图传（带遮挡范围）                 12 MB
│   └── 海康相机 + 镜头 + 17mm测速模块       9 MB
├── 车架5.2.SLDASM                          79 MB   ← base_link,唯一需要下功夫的
│   ├── 【外购件】达妙开发板                 16 MB
│   ├── 【装配体】电池                       4 MB
│   └── 装甲板
├── 【装配体】轮组6.1                        16 MB
└── 分区赛弹仓4.2                            4 MB
```

**关键顺序**：简化几何会改变质量属性。消除特征(Defeature)/另存为零件出来的哑实体(dumb solid)，
SolidWorks 会按简化后的实体**重算**质量——螺丝、轴承、电调全没了，质量直接掉一大截。所以：

**A. 先在全细节状态下抄质量属性。**
对每个 link 子装配 `工具 → 评估 → 质量属性`，输出坐标系设成该 link 自己的坐标系，
抄质量 + 质心 + 惯性张量。

打开 152 MB 总装之前先做一次性设置（`工具 → 选项 → 系统选项`，之后一直有效）：

| 页 | 设置项 | 值 |
|---|---|---|
| **性能** | 以轻化方式自动装入零部件 | ☑ |
| **性能** | 检查过时的轻化零部件 | **不检查** |
| **性能** | 细节层次 | 滑块拉向左侧（细节更少 = 更快） |
| **装配体** | 当装配体中的零部件超过此数量时，使用大型装配体设置以提高性能 | **200** |

最后一条填 200，317 个零件会自动触发**大型装配体模式**，SolidWorks 自己关掉阴影、
透明度、RealView、动态高亮 —— 这些是卡的主因。（这一条在个别版本里挂在**性能**页。）

然后 `文件 → 打开` → 选中文件 → **对话框底部「模式」下拉选「轻化」** →
勾 **「不装入隐藏的零部件」**。

> **别用大型设计审阅(Large Design Review)干这一步。** 它秒开，但只加载图形数据，
> **不能压缩零部件、不能算质量属性**。它只适合先看看树结构、量个尺寸。
>
> 首次打开 144 MB 要建图形缓存，几分钟正常。别强杀 —— 会留下 `~$` 锁文件，
> 下次打开变只读。要中断按 `Esc`。
>
> 打开时若弹「该文件由更新版本的 SOLIDWORKS 创建」，说明队友用了比你更新的版本
> （你装的是 2024），只能让他用 2024 另存。这是唯一硬挡的情况。
> 弹「组件已过期，是否重建」选**不重建** —— 量质量和压缩组件都不需要重建。

**B. 每个 link 单独简化。**
1. 单独打开该 link 子装配
2. `文件 → 另存为` → 类型选 **零件 Part (\*.sldprt)** → 弹窗选 **外部面(Exterior faces)**
   得到单实体哑实体(dumb solid)，内部螺纹孔、沉台、轴承内部结构全消失，面数一般降一个数量级
3. 在派生零件上 `覆盖质量属性`，填 A 步抄下来的真值
4. 命名成 MJCF 的 link 名（`lf0_Link` / `lf1_Link` / `l_drive_bar_Link` / `l_coupler_Link` / `l_wheel_Link`）

**C. 新建导出专用装配体。**
不要在 152 MB 的总装上改。新建 `URDF_export.SLDASM`，只插 11 个简化零件 + §2 的参考几何。
大概 10–20 MB，秒开秒转。

> 好消息：真正卡的只有 `base_link` 一个。腿部子装配全都 2 MB 以内
> （`Left_thigh` 540 KB、`Left_calf` 1.3 MB、`减速箱` 2.0 MB、`腿组5.4` 1.7 MB），
> 直接打开一点不卡。需要消除特征的只有 `车架5.2`。
>
> `车架5.2` 的做法：把 `达妙开发板`、`电池`、`装甲板`、弹仓、裁判系统全部压缩，
> 剩下纯车架结构再「另存为零件」，然后把这些件的质量用「覆盖质量属性」加回 base_link。

### 1.7 剥掉上装：用「压缩」，不是「删除」，更不是「隐藏」

三个操作要分清，中间那个是陷阱：

| 操作 | 从质量属性移除 | 从 URDF 导出移除 | 可逆 |
|---|---|---|---|
| **Delete（删除）** | ✓ | ✓ | ✗ 配合关系一起被删 |
| **Hide（隐藏）** | ✗ **照样算进质量** | ✗ | ✓ |
| **Suppress（压缩）** | ✓ | ✓ | ✓ 右键「解除压缩」 |

「隐藏」是最容易踩的坑：云台在屏幕上消失了，`质量属性` 里质量一克没少，
导出的 `<inertial>` 全是错的。

在 `26分区赛步兵总装` 的特征管理器设计树里右键 → **压缩(Suppress)**：

- `【装配体】云台yaw轴总装03`（60 MB，已含 `【裁判系统】新图传`、`【裁判系统】17mm测速模块`）
- `分区赛弹仓` / `【装配体】弹仓4.2`

`装甲板` **保留** —— 它装在车架上，是底盘的一部分。

副作用是好的：压掉 60 MB 之后总装立刻变轻，§1.6 那个"打开很卡"直接缓解一大半。

**压缩前后各量一次总质量，把差值记下来。** 那就是上装总质量，
以后做带云台变体时直接用，不必再重开 152 MB 的总装。

> 想更规范可以把这套压缩状态存成一个配置(Configuration)叫 `chassis_only`，
> 以后 `with_gimbal` 就是另一个配置。现在只做一个变体的话，直接在默认配置里压缩就行。

## 2. 要建的参考几何清单

导出器对每个关节要两样东西：**参考坐标系**（关节原点）和 **参考轴**（转轴）。

### 2.1 坐标系（左侧 9 个，右侧镜像出来）

所有坐标系统一：**Y 轴 = 转轴方向，指向车体左侧（+Y）**。左右都这样，不要在 CAD 里做符号翻转。

| 名称 | 位置 | 用途 |
|---|---|---|
| `base_link_cs` | 两髋轴连线中点 | URDF 根 |
| `lf0_Joint_cs` | 左髋轴 | 大腿关节 |
| `l_drive_bar_Joint_cs` | 左髋轴（**与上一个同心同点**） | 驱动杆关节 |
| `lf1_Joint_cs` | 左膝轴 | 小腿关节 |
| `l_coupler_Joint_cs` | 驱动杆上的连杆销 | 连杆关节 |
| `l_wheel_Joint_cs` | 左轮轴 | 轮关节 |
| `l_coupler_end_cs` | 连杆末端销（闭链切口，连杆侧） | 闭链约束点 |
| `lf_coupler_closure_cs` | 小腿上的同一个销（闭链切口，小腿侧） | 闭链约束点 |
| `l_spring_p1_cs` | 气弹簧上挂点（大腿上） | tendon 端点 |
| `l_spring_p2_cs` | 气弹簧下挂点（小腿上） | tendon 端点 |

另外建两个和左右无关的（只需一份）：

| 名称 | 位置 | 用途 |
|---|---|---|
| `gimbal_yaw_cs` | 云台 yaw 轴与车架的交点，Z 沿 yaw 轴向上 | `gimbal_Link` 挂点 |
| `gimbal_pitch_cs` | 云台 pitch 轴，Y 沿 pitch 轴指向车体左侧 | 以后要让云台转时用 |

> 云台这两个坐标系现在建几乎零成本，以后想让云台真的动（yaw/pitch 会改变质心和转动惯量）
> 就得重开 152 MB 的总装。顺手建掉。

> `l_coupler_end_cs` 和 `lf_coupler_closure_cs` 在零位时应该**完全重合**——
> 它们是同一个物理销被切开后的两半。

> 气弹簧两个挂点：v3 里被手工投影到了同一个 y 平面（`check_closedchain_model.py:20` 有记录），
> 目的是避免气弹簧产生侧向力。CAD 里按真实位置建就行，需不需要投影我在转换时决定。

### 2.2 参考轴（左侧 5 条）

## 3. 导出器设置

用 ros/solidworks_urdf_exporter（"SolidWorks to URDF Exporter"），装 GitHub Release 里的最新版。

### 3.1 树结构 —— 必须手工切开闭链

导出器**只能导出树，不能导出闭链**。切口选在连杆末端销（coupler ↔ calf），
每侧导出这棵树（和 v3 的切法一致，不要换）：

```
base_link
├── lf0_Link          (大腿)      revolute   ← 髋电机 A
│   └── lf1_Link      (小腿)      revolute   ← 被动膝
│       └── l_wheel_Link          continuous ← 轮电机
└── l_drive_bar_Link  (驱动杆)    revolute   ← 髋电机 B，与 lf0 同轴
    └── l_coupler_Link (连杆)     revolute   ← 被动
```

右侧同构，前缀 `rf0/rf1/r_`。

`l_coupler_end_cs`、`lf_coupler_closure_cs`、`l_spring_p1_cs`、`l_spring_p2_cs`
这四个（每侧）导出器不认——**不要**为它们造假 link。直接在 SolidWorks 里
`质量属性`（输出坐标系设成对应 link 的坐标系）读出坐标，
或者用 `测量` 量，填进 §4 的表交给我。

### 3.2 配置(Configuration)

选 §1.4 建的 `export_visual`，让紧固件不进 STL。

### 3.3 STL 精度

导出器的 STL 选项用 **Fine** 预设即可，不要拉 Custom 到最大分辨率。
导出后我这边跑 `scripts/decimate_visual_meshes.py` 再抽稀一轮
（那个脚本会逐位验证抽稀不改变动力学）。

### 3.4 单位

文档单位设 MMGS 或 MKS 都行，导出器写米。导出后瞄一眼 URDF 里的
`<origin xyz>`，数量级应该是 0.1 这种，不是 100。

## 5. 转换侧（我做）

### 5.1 URDF → MJCF

新脚本 `scripts/build_mjcf_from_urdf.py`，输入上面那批东西，输出 v4 MJCF：

1. 解析 URDF，坐标已经是目标约定，不做轴置换
2. **镜像残差报告**：拿左侧参数镜像到右侧，和 CAD 实际右侧逐项比对，打印每一项的偏差。
   偏差不再被静默保留——要么确认是实车真实差异写进模型，要么归零。
   （v3 的 1.5 mm 就是这么悄悄进去的）
3. 闭链重建：`l_coupler_end` / `lf_coupler_closure` 两个 site + `<equality><connect>`
4. 装配分支限位：两个 `<fixed>` tendon，**加 `rgba="0 0 0 0"`**
   —— v3 里它们被渲染成 58 根垂到 z = −0.57 m 的 capsule，就是 viewer 里那两根"线"
5. 气弹簧：两个 `<spatial>` tendon + 300 N 常力 `<general>`
6. `<default>` class 整理：v3 里 `group="0" contype="1" conaffinity="2"` 重复了 54 次
7. 场景件剥离：`floor` / `light` / grid 材质 / `<visual><global>` 移到独立 scene 文件
   （`robot_cfg.py:26` 现在得在加载时删 floor）
8. `<option>` 补 `integrator` / `impratio` / `iterations`
9. 碰撞体统一到一代（v3 是 `stair_base_visual_coacd_32` + `sw_collision_v3` + `leg_coacd_v1` 三代拼的）
10. mesh 文件名对齐 link 名（v3 里 `lf_calf_1_link.STL` 其实是驱动杆、
    `lf_calf_2_link.STL` 是连杆，名字是骗人的）

### 5.2 两个变体：一个 MJCF + 一个可删除的 `gimbal_Link`

**不要**把云台质量并进 `base_link` 的 `<inertial>`。`base_link` 永远只写纯底盘惯性，
云台作为一个无 joint 的子 body 挂上去：

```xml
<body name="base_link" pos="0 0 0.22">
  <freejoint/>
  <inertial .../>                                  <!-- 永远是纯底盘 -->
  ...腿...
  <body name="gimbal_Link" pos="… … …">
    <inertial mass="…" pos="…" fullinertia="…"/>   <!-- §4 的云台质量属性 -->
  </body>
</body>
```

没有 joint 的 body 被 MuJoCo 焊死在父体上、编译时并进复合惯量 —— 等价于集中质量，
但**它是可删除的**。于是两个变体从同一个文件出：

```python
def _spec(with_gimbal: bool) -> mujoco.MjSpec:
    spec = mujoco.MjSpec.from_file(_MJCF_PATH)
    if not with_gimbal:
        spec.delete(spec.body("gimbal_Link"))
    return spec
```

`robot_cfg.py:19` 已经是这个模式（现在就在 spec 上删 floor），加一行即可。

好处：`base_link` 的惯性只有一份，两个变体不可能漂移；加云台不需要重算底盘惯性
（并进 `<inertial>` 最容易错的地方）；以后想让云台真的转，把 `gimbal_yaw_cs` /
`gimbal_pitch_cs` 对应的 joint 加上就行，不用重新建模。
