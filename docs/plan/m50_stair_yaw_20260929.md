# M50：台阶列 yaw（2026-09-29，用户定）

以 M49 为底，两处改动（改动一、改动二），从头训。

## 改动一：台阶列不采样 yaw 指令，初始朝向正对台阶 ±30°

背景：台阶列（stairs_up、stairs_two_step_up）的 yaw 指令在 ±0.3 rad/s 均匀采样，但 M2 起 `tracking_ang_vel` 在这两列整项置零，
策略看得到 yaw 指令、转不转都不计分。初始朝向是全向均匀 (−180°, 180°)，斜着对台阶角的情况很多。
用户判断随机初始朝向已经提供了足够的转向多样性，不需要再给 yaw 指令；但朝向要收窄到正对台阶。

- `env_cfg(stair_ang_vel_yaw_range=(0.0, 0.0))`：台阶列 yaw 指令恒为 0；其余列不变（平地 ±12 随课程、通用地形 ±0.2）。
- `env_cfg(stair_spawn_yaw_half_range_deg=30.0)`：`reset_root_state_full` 新增可选的 `yaw_sampler` 钩子，rough 的
  `events.stair_facing_yaw` 把台阶列 env 的初始 yaw 改成「随机挑一面台阶（0/90/180/270°）+ U(−30°, +30°)」。
  两种台阶地块都是以出生点为中心、与世界轴对齐的方形环，所以这四个方向就是正对台阶。其余列仍是全向均匀。
- 核验（`.scratch/m50/check_yaw.py`，256 env、四列各 64，换列后刷新指令分列范围）：

| | M49 台阶列 | M50 台阶列 | M50 平地/坡面 |
|---|---|---|---|
| 初始朝向偏离最近正对方向 | 最大 44.9° | 最大 29.7° | 最大 44.8°（不变） |
| yaw 指令最大绝对值 | 0.299 | 0 | 与 M49 相同 |

- rough 41 项测试通过；M50 与 M49 两个入口的 CPU smoke 均通过（共享的 reset 钩子默认 None，旧路径不变）。

## 改动二：台阶列加 yaw 角速度罚（台阶列 yaw 跟踪不再置零）

背景：M2 起 `tracking_ang_vel` 在台阶列整项置零（`tracking_ang_vel_off_terrain`），台阶上转不转都不计分。
改动一把台阶列 yaw 指令定为 0 之后，只要恢复这项在台阶列的计分，它就是一个「机身在转就少拿钱」的 yaw 角速度罚。

- `env_cfg(stair_ang_vel_tracking=True)`（复用 M44 的开关）：`tracking_ang_vel` 去掉按列置零，恢复 Flat 原函数与原参数，
  全列统一：w 3.0、σ 0.25、sigma_cmd_scale 0.4、ratio_blend 0.2、无直立门控。
- 指令为 0 时台阶列每秒扣分（相对不转）：

| 实际 yaw 角速度 | 0.05 rad/s（2.9°/s） | 0.1（5.7°/s） | 0.2（11.5°/s） | 0.3（17.2°/s） | 0.5（28.6°/s） | 1.0（57°/s） |
|---|---|---|---|---|---|---|
| 少拿 | 0.05 | 0.15 | 0.47 | 0.91 | 1.82 | 2.96 |

- 有界：最多每秒少拿 3.0。撞沿时的被动扭转会直接扣钱，M44 的经验是 stairs_up 比同轮次 M43 高 0.3 级、没见摔倒增多。
- 配置核验：相对改动一只变 `tracking_ang_vel` 一项；rough 41 项测试通过，M50 入口 CPU smoke 通过。
