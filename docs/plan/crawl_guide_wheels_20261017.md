# 趴地移动任务与底盘导轮建模（2026-10-17）

## 目标

新技能：机身压在底盘导轮上、两个主轮在后方推动的平地移动。第一版只做平地 vx 跟踪（不转向），出生即趴姿，
以 Flat-MLP（34 维）为底座，入口 `SE3-WheelLegged-Crawl-MLP`（`src/se3_train/tasks/crawl/`）。

## 导轮 MJCF

`assets/robots/serialleg/mjcf/serialleg_closed_chain_v3_guide_wheels.xml` 是正式训练 MJCF 的变体，正式 MJCF 不动，
其余任务不受影响。正式 MJCF 改动时要手动同步到这份。

- 导轮轴：机身底部每侧三根沿 y 的轴，从 `sw_original_base` 视觉 mesh 圆拟合得到轴心
  x = +0.0239 / +0.0019 / −0.0200，z = −0.1259，轴向 |y| 0.1053–0.1281（中点 0.1167），轴心距 22 mm。
- 导轮：直径 20 mm、宽 10 mm（用户给定），无驱动被动 hinge 绕 y 自由滚动。质量 10 g 是估计值，惯量按实心圆柱。
- 导轮 body 排在 `base_link` 子树末尾：原 17 维 qpos 顺序不变，导轮 6 维接在最后，`standing` 关键帧补 6 个 0。
  导轮关节名 `{l,r}_guide_wheel_{0,1,2}_Joint`，不匹配任何 actuator 正则；mjlab 对 init_state 未匹配的关节取 0。
- 机身 CoACD 凸包 01/04/08/09/28 原本比真实 mesh 最低面（z = −0.1305）多凸出最多 7 mm，把导轮整个包住，导轮
  着不了地。变体改用裁到 z = −0.1305 的凸包（`meshes/stair_base_visual_coacd_32_guide_wheels/`，按半空间求交后重求
  凸包），裁后导轮比机身最低面低 5.4 mm。正式 MJCF 仍有这处下凸，现有任务没有依赖它。

原生 MuJoCo 检查（腿和主轮碰撞关闭，只看机身 + 导轮）：前推 10 N 时导轮滚动、1 s 走 0.37 m；侧推 10 N 横向只移动
4 mm；全程无数值发散。导轮几乎没有滚动阻力，松手后基本不减速。

## 趴姿

在导轮 MJCF 上扫 lf0 × 主动杆夹角（policy 语义，机身放在原点、水平），找导轮着地时主轮恰好着地的姿态：

- 主轮只能在机身后方，轮心 x ∈ [−0.32, −0.11] m，腿部碰撞体离地约 3 cm。
- 名义趴姿取 lf0 = +0.611、主动杆夹角 0.767（限位 [0, 1.51] 的正中），主轮心 x ≈ −0.225 m。
  整机质心 x ≈ −0.035，落在导轮与主轮之间，静止即稳定。

注意：扫描时 `mj_resetData` 会把 freejoint 放回 qpos0（z = 0.22 m），必须显式把 `qpos[:3]` 归零。第一版扫描漏了
这一步，得到的“趴姿”主轮实际扎进地下 22 cm，出生后机身被弹起 34°。

名义趴姿 + 腿 PD（kp 60 / kd 3 / 限矩 20 N·m）保持 3 s：

| 气弹簧 | 机身高度 | 俯仰 | 腿偏差 | 支撑分配 |
| --- | --- | --- | --- | --- |
| 关 | 0.1359 m | −0.1° | < 0.01 rad | 导轮 89%，主轮 11% |
| 开（300 N） | 0.1365 m | +1.8° | 约 0.3 rad | 只剩前排导轮 81%，主轮 19% |

气弹簧把折叠的膝往外撑，固定 PD 目标下腿会被撑开约 0.3 rad，机身前倾到前排导轮上，需要策略补偿。主轮只承担
10–20% 体重，摩擦 0.8 下总牵引力约 20 N，是趴地加速度的上限来源；把主轮往前收（x 往 −0.11 靠）可以提高主轮
载荷占比。

## 任务配置（与 Flat 的差异）

- 机器人：`get_serialleg_closedchain_cfg(guide_wheels=True, collision_geom_group=3)`。碰撞 geom 挪到 group 3，
  高度射线 `include_geom_groups=(0,)` 只看地形（critic 高度环半径 0.15 m，趴地时会扫到导轮、主轮和腿）。
- 高度指令固定 0.1359 m（导轮着地时 base_link 原点离地高度）；`flat_base_height` 照常按指令计罚。
- 出生：`reset_crawl_pose`，左右腿各自在名义趴姿上加噪声（lf0 ±0.10、夹角 ±0.05），按主轮底与导轮底的最低点
  把机身升降到离地 2 mm。
- 删除 `stand_still`（零指令时把腿往站立默认姿态拉）。
- 速度课程终值 vx 1.5 m/s。第一版（5rt7ujl1）yaw 包络 3 rad/s；之后用户定不需要转向，yaw 指令恒 0，
  删除恒为 0 的 `tracking_lin_yaw_joint`，`tracking_ang_vel` 保留（跟踪 0 yaw 即保持航向）。
- 动作契约不变：腿目标 = 站立默认姿态 + action × 0.25，ONNX metadata 的 `joint_pos_ref` 仍是站立默认姿态，
  趴姿靠策略输出大偏置实现。

## 第一版结果（W&B 5rt7ujl1，3500 轮）与第二版改动

第一版（yaw 包络 3 rad/s，无导轮/对称专项罚）sim2x 无界面回放：

| checkpoint | 实际 vx / wz 跟踪 | 横滚 | 左 / 右主轮 x | 导轮承重（左 / 右） |
| --- | --- | --- | --- | --- |
| model_500 | 0.79/0.8、1.49/1.5；wz 1.5 指令只转 0.01 | +9~10° | +0.04 / −0.32 | 0% / 45% |
| model_3499 | 0.81/0.8、1.50/1.5；wz 1.48/1.5 | +8° | +0.06 / −0.12 | 0% / 4% |

model_3499 实为低姿态两轮平衡：机身 0.152 m（比导轮着地高 1.6 cm，高度罚只收约 0.4/s），两腿主动杆夹角
都顶在上限 1.51（`dof_pos_limits` 软限位等于机械限位，顶着不扣分），左右腿长差 Δz 5.6 cm 把机身撑歪。

第二版（用户 2026-10-17 定，一起改再训）：

- 不给转向指令，yaw 恒 0（见上节）。
- `guide_wheel_support`（−5）：每侧三个导轮接触合力 / 整机重力为该侧承重占比，低于 25% 的缺口按 25% 归一化，
  左右平均，∈ [0, 1]。按侧计价，单侧抬起同样扣分；按力而非按接触与否，抓得到“导轮轻擦地”。
  新增左右导轮接触传感器，critic 额外观测两侧导轮接触力。
- `wheel_symmetry_offset`（−50/m²）：左右主轮心在机身系的 Δx² + Δz²，定价沿用 Rough M49；与 M49 不同的是
  同时罚 Δz，因为趴地没有 roll 指令。
- 核价：model_500 承重罚 −2.5/s、对称罚 −6.3~−7.3/s；model_3499 −4.6/s、−1.8/s；名义趴姿两项都为 0。
  mjlab 环境里给恒定名义趴姿动作，左右导轮承重 54% / 37%，承重罚 0，机身高 0.1359 m。

## v2 中途结果（W&B nnbqq8h0）与速度课程门控

v2 姿态学对了，速度没学会。sim2x 无界面回放（每段最后 1.5 s 平均）：

| 指令 vx | model_600 实际 | model_1100 实际 |
| --- | --- | --- |
| 0 | −1.77 | −0.35 |
| −0.8 | −1.51 | −0.86 |
| +0.8 | −1.89 | −1.67 |
| +1.5 | −1.92 | −1.81 |

姿态：左右对称（Δx、Δz 毫米级），横滚约 0°，机身 0.137 m，导轮承重 65–73%。训练日志 300 轮起 vx 误差
1.2–1.3 m/s。原生 MuJoCo 里把机身保持在该姿态、用轮速环匀速驱动，−1.8 到 +1.5 m/s 前后对称跟上、导轮承重
不随方向变（注意右轮关节轴是 `0 -1 0`，轮速符号与左轮相反），排除物理限制。

model_1800（每段指令从出生 reset、跑 5 s、取后 2 s）：vx 0 → −0.18，−0.4/−0.8/−1.5 → −0.46/−0.83/−1.58（后退跟上），
+0.4/+0.8/+1.5 → −1.30/−1.13/−0.96（前进仍往后跑）；导轮承重约 80%，左右对称。训练日志 tracking_lin_vel 从 1300 轮的
1.43 升到 1500 轮的 1.88（vx 误差 0.89），涨的是后退那一半。用户 2026-10-17 在第 2067 轮停掉 v2（最后 checkpoint
model_2000），改用下面的课程门控重训。

根因：第 100 轮时导轮承重还接近 0、承重罚顶满，速度课程已按跟踪 EMA 0.52 推到 vx 1.4（vx=0 阶段跟踪分走
sigma_stand，姿态没学会也能过 0.5）；姿态在 300–700 轮才形成，此时跟踪 EMA 掉到 0.16–0.18，但退级关闭，
课程锁在 1.5，策略在宽指令下学成“姿态对、速度不管”。

改法（用户 2026-10-17 定）：`curriculums.commands_vel_after_crawl_posture` 包一层 `commands_vel_adaptive`，
导轮总承重 EMA（读 `Crawl/guide_share_total`，与跟踪分同一节流）≥ 0.5 之前把推进阈值临时设为 +inf，
只停推进、不回退。crawl 两项奖励的日志同时改为每 64 步写一次。验证：mjlab 环境里给恒定名义趴姿动作，
导轮总承重 0.88，门控打开；随机策略 smoke 中门控保持关闭、vx 上限停在 0。

## v4：动作零点改为趴姿 + 趴姿姿态罚

v3（9qjvkgb3，速度课程门控）在只给 0 指令时姿态学得比 v2 慢约 300 轮：第 600 轮导轮承重罚才从 −5 开始下降。
根因是动作零点：腿目标 = 实体默认姿态 + 动作 × 0.25，默认是站姿，趴姿要一直输出 (3.1, 5.3, −3.1, −5.3) 的大偏置；
初始化时零动作把机器人拉成站姿，探索也以站姿为中心。

改法（用户 2026-10-17 定，与姿态罚绑定为一个变量）：

- crawl 实体 `init_state.joint_pos` 改为名义趴姿（`events.crawl_default_model_joint_pos`，被动关节按解析闭链补齐），
  零动作即趴姿。mjlab 训练配置（含 DR）给零动作 250 步：机身 0.136 m、直立、导轮承重罚 0、左右对称。
- ONNX 的 `policy_io.action.offset` 与 `references.joint_pos_ref` 改为从 robot 实体 `init_state.joint_pos` 读名义值
  （`onnx_metadata._policy_default_joint_pos`），不再写死 `RobotConfig().default_dof_pos`；不读运行时
  `default_joint_pos`，因为 startup DR 会逐 env 叠 ±0.05 rad。Flat 导出值不变；crawl 导出
  (0.611, −0.156, −0.611, 0.156)，sim2x 按 `entity_default_joint_position` 解码，无需改 runtime。
  **真机固件若写死站姿默认角，上车前要改成读 metadata。**
- 新增 `crawl_pose_deviation`（−1.0）：四个 policy 腿关节偏离“零动作沉降趴姿”的 L2 范数。参考 = 实体默认姿态 +
  气弹簧沉降偏移 `crawl_spring_sag`（原生 MuJoCo 名义 PD 静置 3 s 实算并缓存，(−0.285, +0.318, +0.285, −0.318) rad）。
  直接以名义趴姿为参考时零动作就偏 0.54–0.68 rad，策略只能一直出力顶弹簧（约 8.6 N·m/关节）；改成沉降姿态后
  零动作残差 0.06–0.18 rad（弹簧力、PD、电机被动参数 DR）。不复用 `joint_pos_penalty`：它按高度指令查站姿默认表。
- 速度课程门控（v3）保留。远端速度误差罚（轮速环路增益约 1.2 的问题）不在本版，单独做。

## v4 结果与 v5：actor 换成 Rough 的小网络

v4（f96ibzjn）model_500 sim2x 逐档回放（每档 reset、取后 2 s）：vx 0/+0.4/+0.8/+1.5/−0.4/−0.8/−1.5 →
0.00/+0.39/+0.80/+1.42/−0.42/−0.80/−1.41；不 reset 连续切指令 0→+0.8→+1.5→−0.8→0 也不发散（−3.8 m/s 的轮速正反馈消失）；
导轮承重 81%、左右对称、机身 0.136 m。零动作改为趴姿同时消掉了前进学不会与轮速正反馈两个问题，远端速度误差罚暂不需要。

但 v4 的 actor（34→512→256→128→6，18.3 万参数、FP32 715 KB）上不了 STM32H723：片内 Flash 放不下（代码约 124–141 KB），
外部 Flash 上同尺寸的 RJ1 实测 41.7 ms/次，超过 20 ms 周期。用户 2026-10-17 在第 1066 轮停掉 v4（最后 checkpoint model_1000），
v5 只把 actor 隐藏层换成 Rough 的 (128, 64, 32)（约 1.5 万参数、59 KB），critic 与其余配置不变。

固件侧（serialleg2026，只读排查）：34 维单帧观测、趴姿 offset、wheel scale 15 都已由 metadata 驱动、无需改；
需要改的是增益（训练 60/3/0.2，主工程默认 30/2/0.1，用 -D 覆盖或改默认）与 `validate_stm32_runtime.py` 里无跳跃轨道时仍断言起跳的检查；
上电前必须把机器人摆成折叠趴姿再切 MID（固件没有插值起身，直接以 offset 为目标）。

## 斜坡版：SE3-WheelLegged-Crawl-Slope-MLP

用户 2026-10-17 定（v5 上车测试通过后）：MDP 与 v5 完全相同，只加上坡地形；坡度 0–0.15、只要上坡、先修底部碰撞体、
姿态项改为相对坡面。

- **机身底部凸包分段**（导轮变体 MJCF，平地 crawl 同样生效）：凸包 01/04/08/09/28/25 原本把导轮支架处的最低面
  （z = −0.1305）铺满 x −0.17~+0.26，真实结构在支架以外高 1.5~3 cm。沿 x 在 −0.2/−0.08/−0.05/+0.05/+0.08/+0.2 切开，
  每段底面裁到该段视觉 mesh 真实最低点（−1 mm 余量），6 块 → 24 段（`meshes/base_bottom_sliced_v1/`，每段范围见
  `slices.json`；原 `stair_base_visual_coacd_32_guide_wheels/` 删除）。名义趴姿接近角 3.1°→6.6°、纵向通过角 6.1°→12.1°
  （视觉 mesh 7.8° / 17.6°）。按 7 cm 自适应切片会切出 97 块且锯齿严重，没有采用。v5 model_900 在新碰撞体上的平地
  sim2x 逐档结果与旧碰撞体逐项相同；sim2x v2 契约不校验 MJCF 哈希，v5 ONNX 照常加载。
- **地形**（`crawl/terrains.py`）：只有 `hf_pyramid_slope_inv`（出生在坑底 2 m 平台、四周上坡），坡度沿行从 0 插值到 0.15，
  10 行 1 列，块 9 m、hfield 0.2 m、边框同 Rough；官方 `terrain_levels_vel` 升降级，加 `terrain_edge_reached`
  （门槛 1.0 个半边长）与 `out_of_terrain_bounds` 截断，接触匹配槽 500。0.15 坡（8.5°）高于接近角 6.6°，坡底凹折处车头会轻擦，
  真车（7.8°）同样会擦。
- **相对坡面姿态项**：机身下方 3×3 射线（间距 0.15 m、yaw 对齐、只看地形）取命中法线均值作局部坡面法线 n，
  机身系里的 −n 代替 projected_gravity 计算 pitch/roll 与倾角；`tracking_orientation_l2_terrain`（−12）与
  `bad_tilt_terrain`（−6，10°/30°）权重参数不变，平地上与原项等价。`bad_orientation` 终止（绝对 30°）保留。
- 核对：mjlab 斜坡环境里用 v5 model_900 前进/后退，倒着爬 6.7° 坡时绝对倾角 4–6.6°、相对坡面 0.2–1.2°；
  中等坡度能爬上去，最陡档后退爬到一半失速，留给训练。本地 CPU smoke 通过。
