# M2：台阶列去工资、去爬升税、加摔倒罚（2026-09-13）

对照基线：M1（W&B hqcn4y2f，commit 671db84 + 两列地形/池容量性能改动）。成因分析见
`m1_model800_vs_1400_20260913.md`。用户 2026-09-13 定：只做这一组定价改动，不加高姿起步转移、不加卡住终止。

## 假设

M1 台阶列账本（每秒贡献）："冻住不动"净 +0.94/s（is_alive +1.0、零速时跟踪核仍 +0.54、违令罚 −0.60），
"努力爬"在 1600 轮净 −0.4/s，其中轮离地罚 −0.7、base 碰地形罚 −0.5 正好罚在抬轮跨立面这个动作上。
官方升降级把台阶 env 堆在成功率约一半的行；按此账本"尝试"要成功率超过约 40% 才比"冻住"划算，
去掉工资后约 12%。1400 轮确定性回放长出的常数动作不动点是这个失衡的产物。

## 改动（commit 见 handoff）

| 项 | M1 | M2 |
|---|---|---|
| `is_alive`（+1/s） | 全列 | 台阶列置零 |
| `flat_wheel_contact`（轮离地，−10） | 全列 | 台阶列置零 |
| `collision`（base 碰地形，−16） | 全列 | 台阶列置零 |
| `fall_penalty` | 无 | mjlab `is_terminated`，每次非超时终止（灾难、倾倒）一次性 −10；权重 −500 = −10 / step_dt 0.02，因 RewardManager 按 dt 缩放 |
| 其余（台阶专项奖励、跟踪核、违令罚、课程、热身、地形） | 同 | 同 |

三项置零走 `rewards.off_column` 通用包装（原函数与原参数逐位沿用 Flat，只在 `stairs_up` 列乘零）。
摔倒罚全列生效：工资拿掉后台阶列每秒净值接近 0，非超时终止按 0 自举等于"免费退出"，没有摔倒罚时提前摔死会变便宜。

改动后台阶列账本预期："冻住"≈ −0.06/s（跟踪核零速项 +0.54、违令罚 −0.60），"会爬"的策略按 A15 4900 轮账本
去掉两项税后约 +1.65/s；摔倒 −10 一次。

## 验收

与 M1 同一套确定性回放（`.scratch/m1_eval/`）：平地固定指令扫描、台阶停走探针、1–9 级台阶通关、
MJLab 逐 env 卡住率；对照 M1 同轮次的 model_800 / model_1400 与 M1 跑完后的 model_4999。
关注：台阶通关率是否不再随轮次塌下去；确定性回放是否出现常数动作不动点；摔倒率（`Episode_Termination/catastrophic_state`、`bad_orientation`）
在去掉两项税后是否上升，以及 `Episode_Reward/fall_penalty` 的量级。

## 口径差异

M1 用 4 卡（每轮 32768 样本），M2 因 M1 仍在跑只有 4、5 两卡可用，每轮 16384 样本；A13b 曾在 1× 与 4× 下得到相反结果，
同轮次比较带批量混杂，需要时 M1 跑完后用 4 卡复跑。
