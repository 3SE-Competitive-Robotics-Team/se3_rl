# M35 / M36：上台阶提速的两条单变量对照（2026-09-26，用户定）

## 问题

M34（acqxnyu8）能上 20 cm 台阶，但慢：台阶列训练均速 0.65 m/s 对指令均值 1.38。用户的假设是 action_rate 罚太大。

## 反事实账本（M34 `model_7800`，第 9 级 20 cm、踏面 0.7 m、h=0.34，确定性回放）

MJLab CPU 环境按 M34 三个开关构造（窗口高度参考、两项轮几何罚零死区），同一策略按"观测指令 ≠ 计酬指令"跑，
读 `RewardManager._step_reward` 得到每项每秒贡献。脚本 `.scratch/m34_eval/stair_ledger.py`，
结果 `stair_ledger_m34_7800_window.json`。

> 第一版账本误用了 `env_cfg(play=True)` 默认配置（M21 支撑面口径 + M27 轮死区），高度罚数字偏大一倍，已重跑；
> 动作罚不随速度变的结论两版一致。

行为（观测指令 → 爬升段均速 / 整块用时 / 触面速度）：

| 指令 | 通关 | 用时 | 爬升均速 | 四道立面触面 vx |
|---|---|---|---|---|
| 0.6 | 否，卡第一道立面 | — | — | 0.39 |
| 1.0 | 是 | 5.50 s | 0.73 | 0.75 / 0.93 / 0.87 / 0.77 |
| 1.4 | 是 | 4.94 s | 0.81 | 1.19 / 1.00 / 1.17 / 1.03 |
| 1.8 | 是 | 4.66 s | 0.89 | 1.22 / 0.89 / 1.36 / 1.08 |
| 2.4 | 是 | 4.72 s | 0.86 | 1.09 / 1.15 / 1.67 / 1.07 |

策略只有一种约 0.85 m/s 的爬升模态，指令 1.4 以上不再提速。

按指令 1.0 计酬的每秒账本：

| 行为 | 均速 | 每秒总 | 宽核 | 支撑 | 进度 | 高度罚（窗口） | action_rate | 平滑罚 |
|---|---|---|---|---|---|---|---|---|
| cmd 1.0 自身 | 0.73 | 8.22 | 5.64 | 2.91 | 1.48 | −0.63 | −0.57 | −0.14 |
| cmd 1.4 的行为 | 0.81 | 8.39 | 5.46 | 3.24 | 1.64 | −0.85 | −0.55 | −0.12 |
| cmd 1.8 的行为 | 0.89 | 8.32 | 5.48 | 3.43 | 1.75 | −0.98 | −0.58 | −0.14 |
| cmd 0.6 的行为（卡住） | 0.07 | 0.06 | 3.37 | 0 | 0 | −1.80 | −0.22 | −0.07 |

按指令 1.4 计酬：0.73 → 6.57，0.81 → 7.08，0.89 → 7.32，2.4 的行为（0.86）→ 6.63。

结论：

- **action_rate / action_smoothness 与爬升速度无关**（三种速度 −0.55…−0.58 / −0.12…−0.14），不是刹车。
- **唯一随速度明显上涨的罚项是窗口口径高度罚**：每快 0.08 m/s 多付约 0.22/s，抵掉支撑 + 进度 + 窄核增益（+0.59/s）的四成。
- **指令 1.0 定价近乎平坦**：0.73 与 0.89 m/s 每秒只差 0.1，策略没有提速动力；卡住则被重罚（0.06/s），所以不会退化成不动。
- 待查反常：cmd 1.0 计酬下 0.81 m/s 的宽核（5.46）低于 0.73 的 5.64，指令更近却拿更少，可能是快速时速度波动更大。

窗口高度误差方向（`.scratch/m34_eval/window_height_err.py`）：误差 68–86% 的时间为**机身偏低**（p10 −8…−10 cm），
罚款 80% 落在过沿过渡段；单边只罚偏低几乎不省（0.62 → 0.58/s），±5 cm 死区把每秒罚压到 0.09 / 0.15 / 0.22
（对应 0.73 / 0.81 / 0.89 m/s），随速度上涨的部分从 0.22/s 降到 0.06/s。

## 两条对照（均以 M34 为基线，唯一变量）

| 编号 | 任务入口 | 唯一变量 | 预期 |
|---|---|---|---|
| M35 | `SE3-WheelLegged-Rough-Exp-HeightWindowDz5NoWheelDeadzone` | 上台阶列窗口高度罚 ±5 cm 死区（`stair_height_dead_zone_m=0.05`） | 台阶列 `rw_flat_base_height_stairs` 从 −1.36 回到约 −0.4；爬升均速 0.73 → 0.85 以上 |
| M36 | `SE3-WheelLegged-Rough-Exp-HeightWindowNoWheelDeadzoneProgress6` | `stair_climb_progress` 权重 3 → 6 | 1.0 定价下 0.73 与 0.89 m/s 的每秒差从 +0.1 变成 +0.4 以上 |

配置差异核验：`env_cfg` 逐项对比，M35 只有 `flat_base_height.dead_zone_m 0 → 0.05`，M36 只有 `stair_climb_progress.weight 3 → 6`。

## run 设置

nulltask1，各三卡 × 8192 envs（M35 GPU 0–2，M36 GPU 3–5，`-AllowConcurrent`），4000 轮、保存间隔 200、seed 42，
W&B project `SE3-WheelLegged-Rough`。M34 的台阶等级 2000 轮到顶、速度 4000 轮后只从 0.53 涨到 0.58，4000 轮够筛选。
每轮样本量是 M34 的一半，按同 iteration 比较有批量混杂。

## 验收

- 每个 checkpoint 跑确定性回放，W&B 曲线只作辅助。
- 速度：`stair_ledger.py` 改 ONNX 路径，看 cmd 1.0 / 1.4 的爬升均速与触面速度；目标 1.0 指令下均速 ≥ 0.85、整块 ≤ 4.6 s。
- 流形：`.scratch/m18_eval/riser_events.py` 看触面后双轮抬起时序与左右轮高差，走梯和起跳都算失败。
- 能力：`.scratch/m15_diag/climb_speed_map.py` 第 6/8/9 级 × 0.6–2.4 通关图不比 M34 差。
- 平地：`.scratch/m15_diag/sweep.py` 0.2–2.4 传递曲线低速段不低于 M34。
- W&B：`Rough/base_vx_stairs`、`Curriculum/terrain_levels/stairs_up`、`Rough/wheel_dz_abs_stairs`、
  `Episode_Termination/catastrophic_state`。

## 停止与结论

2026-09-27 约 13:20（Pod 时区）按用户指令 SIGINT 停止，M35 停在 1810 轮（最后 checkpoint `model_1800`），M36 停在 1792 轮
（最后 checkpoint `model_1600`）。W&B 在开跑 10 分钟处断连（boring 隧道 closed + 网关维护循环假活），12:37 重开隧道并
End/Run 网关任务后补传完整。

末 40 轮均值（M34 同期取 1800 轮附近）：

| 指标 | M35 | M36 | M34 同期 |
|---|---|---|---|
| stairs_up 等级 | 5.80 | 6.26 | 5.72 |
| 台阶列实际 vx | 0.51 | 0.53 | 0.52（2000 轮） |
| 台阶列高度罚 /s | −0.96 | −1.73 | −1.65 |
| 台阶列进度奖励 /s | 0.59 | 1.12 | 0.62 |
| 台阶列支撑奖励 /s | 1.42 | 1.35 | 1.48 |
| 台阶列 action_rate /s | −1.23 | −1.30 | −1.15 |
| 台阶列左右轮高差 |Δz| m | 0.027 | 0.033 | 0.024 |
| 灾难终止 | 0.28 | 0.32 | 0.04 |
| 全列 mean_reward | 19.1 | 21.0 | 20.5 |

- 两条的变量都按预期生效：M35 高度罚只有 M34 的 58%；M36 进度奖励实付接近翻倍，但高度罚同时升到 −1.73，
  即它为多拿进度奖励爬得更急、过沿时机身偏低更多，正是账本预言的那笔成本。
- 1800 轮内两条的台阶列速度都还没与 M34 拉开（0.51 / 0.53 对 0.52），课程上 M36 领先。
- 两条灾难终止都在 0.3 左右，M34 同期 0.04；两条一样高，属三卡样本量减半的批量效应，不归因于各自变量。
- **用户判定**：sim2x 回放两条的 `model_1600`（1 到 9 级金字塔场景）后认为 M35 效果更好，保留 M35 配置，M36 入口删除
  （复现用 commit `5af0d00`）。`SE3-WheelLegged-Rough-Exp-HeightWindowDz5NoWheelDeadzone` 为当前 rough 线的保留配置。
- 本轮没有跑完 4000 轮，也没有做确定性账本与通关图；速度结论仍待后续在 M35 配置上跑满后按验收流程补做。
