# A15 启动失败原因分析（2026-09-11）

结论：现有证据最支持“停稳后进入另一组物理姿态/策略响应，训练未充分学会从该状态启动”。训练端的高姿停走覆盖不足与起步阶段奖励权衡，是两个有源码依据的成因候选；尚未用训练消融证明因果份额。不能说静止已被证明是全局最优。

## 已证实的直接机制

model4999在.38高度指令下停稳后，2.4速度指令持续30s仍约.057m/s。运行时保留qpos清全部qvel及runtime仍可再启动，说明单纯惯性或runtime状态不是必要条件；但这时实际高度约.294m，与停滞时.352m不同。直接证据是状态依赖，不是“同一真实高姿下已证明机械可起步”。

停滞时轮raw约[.257,.030]，运行时约[3.84,-3.57]，策略没有给出相同的持续轮驱动。运行中.38高度指令实际只有约.29–.30m；学到的可运动姿态未满足高度要求。

## 训练覆盖缺口（事实）

A15实际W&B config：flat30%、stairs_up70%；台阶重采样时standing_ratio强制0；平地standing_ratio=.1，standing_height_range=.20–.38；每5s同时重采速度、pitch、roll与高度，height_resample_on_reset_only=False。

仅按计划分布，全部环境中平地高姿(.35–.38)静站占比约.3*.1*(.03/.18)=.005，即0.5%。这不是实际稳态占比；也不是绝对没有停走样本。尤其没有保证下一段保持相同高度、姿态指令再启动。大量训练环境不等于覆盖了部署中的固定高姿停走转换。

## A15仍有起步收益障碍（公式证据，非完整轨迹回报）

平地速度两项实际参数：4*exp(-(v-vcmd)^2/.5)，以及-2*(max(abs(v-vcmd)-.05,0)/3)^2（忽略yaw、未到封顶）。vcmd=2.4：从v=0到.1，跟踪正奖励约.000040→.000102，违令罚约-1.227→-1.125；合计只改善约.102/秒。PPO不对该函数直接求动作梯度，这些数字表示探索结果之间的回报分辨度。

高度罚仍为-4*(高度误差/.1)^2。示例：误差从2cm变3cm，单这一项即多罚.20/秒；这是标量敏感度示例，不是已经测到的同一条起步动作账本。再加姿态、动作变化等代价，可能让短期探索难以获得正优势。A15不是完全没有速度误差信号，放宽后也不能保证任何初态都能跨过低收益转换段。

该高速度示例不能单独解释所有失败：.8指令同样不能在高姿启动，表明还需考虑已有策略的状态分布与姿态响应，不能只归因于2.4指令下指数奖励小。

## 高度跟踪与多任务权衡

70%台阶列关闭精确高度罚、速度核更宽(1.44)，平地保留高度罚、速度核.5。共享策略面对不同地形上的不同约束；台阶高度指令不是严格高度跟踪目标。当前实测降姿运动和超速与这种宽松约束相容，但尚未证明分列奖励是唯一原因。误差核以指令速度为中心，公式本身并不直接奖励超速。

## 下一步最有信息量的验证

若继续定位，先以A15真实训练奖励核算同模型起步转换轨迹，再做固定高姿停走覆盖×起步收益修改的对照，保留原爬阶验收。核算平面轨迹时务必保留flat列身份：terrain_column_mask在无generator的plane环境返回None，command_velocity_error_on_terrain会返回0；直接沿用旧plane探针会漏算A15已经放开的违令罚。

本次只分析现有轨迹、W&B配置快照与源码并计算公式，未新跑训练或声称已得到完整A15回报账本。

## 2026-09-11 A15 reset机制核实与解释修正

- A15实际W&B reset配置为full_joint_randomization=True、full_front_joint_offset_range=1.57、align_root_height_to_wheels=True、wheel_clearance=.001；不是按高度指令生成稳态高姿。默认root高度.22，后续按轮净空抬升；前关节相对共享默认各±1.57rad、主动杆夹角在合法范围采样，闭链被动关节同步构造。
- reset_root_state_full默认recovery_prob=0，A15 jump_prob=0：root线/角速度置0；关节与轮速度默认范围也为0。机身保持直立，yaw随机、xy±.1m。ActionManager清当前及历史raw actions，A15没有A14的reset last_actions随机化。
- reset_root预采指令，台阶立即得到vx1–2.4、按地形下限约束的高度指令；没有先等高姿零速站稳的阶段。出生平台宽2m提供接近首阶的空间。
- 因此必须修正“训练缺少零速开局”的泛化说法：训练大量零速开局，但随机非平衡姿态+清动作历史+立即运动，不等于策略形成的高姿静站稳态。随机姿态覆盖广也不能直接推断已充分覆盖该窄分布。
- 本次核对源码与A15配置，没有测训练reset后的实际状态分布或开局成功率，不断言每个reset都能起步爬阶。



## 台阶两项奖励与速度的关系

- `stair_climb_progress` 返回 `delta_progress / step_dt * upright`，权重+3；RewardManager启用`scale_rewards_by_dt=True`，实际每步贡献为`3 * delta_progress * upright`。因此瞬时每秒账面近似`3 * v_outward`，没有速度误差门控；但固定走完同样距离时累计总额近似相同，速度主要通过更早获得奖励、减少超时间接占优。
- `stair_support_height` 返回每次新支撑阶数`gain / step_dt`，权重+4；经过RewardManager的dt缩放后，一次gain=1的累计贡献是+4，而不是持续+4/s。速度不会改变单阶金额，但会提高在episode内触发阶数、在终止前完成支撑的机会；一次candidate跳过多阶时可能一次结算多个gain。
- 因而两项都与速度相关，但强度不同：进度项是直接的速度相关 shaping，支撑项是通过到达/完成时限间接相关。不能把进度项称为无限加速奖励，也不能把支撑项当连续速度奖励。
