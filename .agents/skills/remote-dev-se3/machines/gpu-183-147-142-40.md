## 运行环境

容器默认 `LD_LIBRARY_PATH` 会优先加载系统 cuDNN 9.8，但当前 PyTorch 需要随 wheel
提供的 cuDNN 9.19。训练和 smoke 必须使用 `env -u LD_LIBRARY_PATH ...` 启动，避免
覆盖 PyTorch wheel 的动态库解析顺序。

## 单卡训练队列

这台机器使用单 worker 串行调度训练，禁止在队列外并发启动第二个 `se3-train`。

| 项目 | 路径 |
|---|---|
| 队列根目录 | `/root/gpufree-data/se3_queue` |
| SQLite 状态 | `/root/gpufree-data/se3_queue/queue.db` |
| worker 日志 | `/root/gpufree-data/se3_queue/logs/queue-worker.log` |
| 任务 stdout | `/root/gpufree-data/se3_queue/logs/jobs/job-<id>.log` |
| checkpoint / ONNX / run | `/root/gpufree-data/se3_queue/checkpoints/<task>/<run>/` |
| W&B 本地缓存 | `/root/gpufree-data/se3_queue/wandb` |
| CLI | `/usr/local/bin/se3-queue` |
| 当前 worker tmux | `se3_queue_worker` |
| 重启自启动配置 | `/.gpufree/se3_queue.conf` |

提交和查看任务：

```bash
se3-queue submit SE3-WheelLegged-Recovery-Loco-Grouped-MLP \
  --name recovery-loco-grouped-history-mlp \
  --envs 8192 \
  --iterations 5000 \
  --save-interval 200
se3-queue list
se3-queue show <job-id>
se3-queue tail <job-id> --lines 100
se3-queue cancel <job-id>
```

任务提交时固定当前 git commit，worker 启动前会执行 CPU smoke，并通过训练 CLI 的
`--log-root` 直接把完整 run 写入数据盘。API key、Token 等敏感值不得通过
`se3-queue submit --env` 写入 SQLite；W&B 使用本机 `/root/.netrc`。

在队列部署前已经运行的训练无法热切换 `--log-root`，worker 会把它识别为外部训练并
等待结束。之后由队列启动的任务全部使用数据盘路径。
