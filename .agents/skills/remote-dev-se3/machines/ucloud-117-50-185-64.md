## 单卡训练队列

这台机器使用 supervisor 管理一个以 `ubuntu` 身份运行的单 GPU worker，任务严格串行
执行；worker 会等待队列外的 `se3-train` 进程结束。默认参数为每卡 8192 个环境、
5000 轮、每 200 轮保存，W&B online。

| 项目 | 值 |
|---|---|
| CLI | `/usr/local/bin/se3-queue` |
| supervisor program | `se3_queue_worker` |
| supervisor 配置 | `/etc/supervisor/conf.d/se3_queue.conf` |
| worker 自启动 | `supervisor.service` 已启用 |

```bash
se3-queue submit SE3-WheelLegged-Recovery-Loco-Grouped-MLP \
  --name recovery-loco-grouped-mlp
se3-queue list
se3-queue show <job-id>
se3-queue tail <job-id> --lines 100
se3-queue cancel <job-id>
```

任务提交时固定当前 git commit，启动前默认执行 CPU smoke。W&B 凭据位于权限为 600 的
`/home/ubuntu/.netrc`，当前验证 entity 为 `luzhongjin365-se3`；不得把 API key、Token
或密码通过 `se3-queue submit --env` 写入 SQLite。

私有 `se3-sim2x` 初始 checkout 由本地完整 Git bundle 建立，远端 origin 保持官方
HTTPS 地址，但服务器不保存个人 GitHub 凭据。将来主仓库更新 submodule 指针时，应为
该私有仓库配置只读 deploy key，再执行 `git submodule update --init --recursive`。

## 连接注意事项

UCloud 外网防火墙的 TCP 22 来源宜限制为可信出口 IP 的 `/32`，不要长期开放
`0.0.0.0/0`。修改规则前必须重新核验当前出口 IP，避免动态公网 IP 变化导致锁定。
后续运维优先使用 `ssh ucloud-se3` 并复用持久连接。
