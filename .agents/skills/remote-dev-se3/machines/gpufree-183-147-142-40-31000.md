## 独立常驻 sim2x

sim2x 与训练启动入口完全解耦，服务器保持一个独立的 `se3-sim2x-browser`。扫描
`/workspace/se3_data/logs`，因此 `formal` 和 `rsl_rl` 下所有 run 新导出的 ONNX 都会自动
出现在浏览器列表中；当前仍需在 GUI 中手动选择 active policy。

browser 固定识别 `<root>/<experiment>/<run>/onnx` 两级布局；`logs` 根目录下用
`formal__<experiment>` / `rsl_rl__<experiment>` 相对软链接合并两棵现有 experiment 树。
新增 run 会自动出现；新增从未存在过的 experiment 时需补一次同名来源软链接。

```bash
/workspace/se3-config/manage_sim2x_sidecar.sh ensure \
  --repo-root /workspace/se3_rl \
  --run-root /workspace/se3_data/logs \
  --state-dir /workspace/se3_data/live-control/sim2x-serialleg \
  --env-file /workspace/se3-config/se3-env.sh \
  --host 127.0.0.1 \
  --port 8080 \
  --cpu-list 120-121 \
  --wait-timeout 600 \
  --label serialleg-all-runs
```

约束与运维信息：

- 仅监听 `127.0.0.1:8080`，不得改成公网地址；本机通过 SSH local forward 访问。
- 强制 `CUDA_VISIBLE_DEVICES=''`，CPU affinity 为 `120-121`；实测约占半个 CPU 核，
  `nvidia-smi` 中没有 sidecar 进程。
- 生命周期命令为管理脚本的 `ensure/status/log/stop/restart`；`stop/restart` 仅作用于 state
  中校验过的 sidecar PID/PGID，不得用于训练 PGID。
- 本机用 `boring` 保持自动重连的 SSH local forward：

  ```powershell
  boring open gpufree-4090-sim2x
  boring list
  boring close gpufree-4090-sim2x
  ```

在 4×4090、每卡 8192 env、24 steps 的正式训练中做了 4×30 iter 的 ABBA 测试：
collection time 对称效应 `-0.038%`，moving-block bootstrap 95% CI
`[-0.352%, +0.279%]`；总 iter time 点估计 `+0.488%`，95% CI
`[-0.099%, +1.291%]`。总耗时点估计由 B1 的 3 次 learner 瞬态抖动主导，B2 未复现；
结论是未检测到可归因于 sidecar 的训练减速。

## GPU-aware 训练队列

单机整卡独占调度器支持任务申请 1、2 或 4 张 GPU；同优先级 FIFO，按 `priority DESC,
id ASC` 调度。只要队首任务放不下，就停止启动后续小任务并等待现有任务排空，因此四卡
任务不会被连续的小任务饿死。手工启动的外部 `se3-train` 不属于租约，worker 会保守地
暂停全部新调度。

| 用途 | 路径/值 |
|---|---|
| 调度器 | `/workspace/se3-config/se3_training_queue.py` |
| 调度器 SHA256 | `e5755cac93467bdaf66b2ac863d9e55343df70e8e7091731917a7e7d8895c932` |
| CLI 入口 | `/workspace/se3-config/se3-queue` |
| worker 启动脚本 | `/workspace/se3-config/run_gpu_queue_worker.sh` |
| 持久状态/W&B/日志 | `/root/gpufree-data/se3-queue` |
| 训练产物 | `/workspace/se3_data/logs/formal` |
| tmux session | `se3-gpu-queue` |
| 受管 GPU | `0,1,2,3` |

常用命令：

```bash
# 提交；--envs 表示每卡环境数
/workspace/se3-config/se3-queue submit <task> --gpus 1 --envs 8192 --iterations 5000 --name <run-name>
/workspace/se3-config/se3-queue submit <task> --gpus 2 --envs 8192 --iterations 5000 --name <run-name>
/workspace/se3-config/se3-queue submit <task> --gpus 4 --envs 8192 --iterations 5000 --name <run-name>

# 可观测与控制
/workspace/se3-config/se3-queue list
/workspace/se3-config/se3-queue resources
/workspace/se3-config/se3-queue show <job-id>
/workspace/se3-config/se3-queue tail <job-id> --lines 100
/workspace/se3-config/se3-queue cancel <job-id>
```

训练参数通过 `--extra-arg=<argument>` 逐项追加；`--gpu-ids` 与
`CUDA_VISIBLE_DEVICES` 由队列独占管理，禁止任务覆盖。worker 当前由 tmux 常驻：

```bash
tmux attach -t se3-gpu-queue
tmux capture-pane -pt se3-gpu-queue -S -100
```
